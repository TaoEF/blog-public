# Large Change Workflow

Use for shared paths, contracts, schemas, architecture, or multi-domain changes.

1. Read harness and wiki context.
2. Inspect current code and tests.
3. Produce an implementation plan.
4. Produce test cases.
5. Get user confirmation.
6. Implement progressively.
7. Preserve backward compatibility unless explicitly approved.
8. Run planned verification.
9. Update wiki/harness when durable knowledge changes.
